# мини ПМ — описание продукта для формы сдачи

Команда «всеmogущие» · трек «Цифровой аватар» · задача «ИИ-помощник продукт-менеджера интернет-магазина» (Софтлайн, store.softline.ru)

- Стенд: https://77-233-220-24.sslip.io (запасной: https://mini-pm.onrender.com)
- Репозиторий: https://github.com/Toolk23/mini-pm
- API: https://77-233-220-24.sslip.io/docs

## Коротко
мини ПМ — агент, который берёт на себя рутину продакт-менеджера: сам замечает устойчивые отклонения метрик,
расследует причину по всем источникам (Метрика, релизы, бэклог, интервью, конкурентный анализ, поиск Яндекса, живая витрина),
предлагает и оформляет действия (задача в бэклог с тегом «сгенерирована ИИ-помощником», приоритеты, гипотеза с критерием,
письмо ПМу), после релиза измеряет эффект — и готовит для отдела продаж справку и ответы на повторяющиеся вопросы.

## Реализовано за время спринта
1. **Радар сигналов.** Детерминированный детектор по данным задачи: скользящее среднее за 4 недели, исключение разовых
   всплесков (медиана 4 предыдущих недель × 1,35), пометка неполной недели, контрольная группа, окно релизов,
   реестр разрывов учёта («нет данных» ≠ ноль). На данных задачи: самостоятельные заказы KES −32,7% (165,8 → 111,6),
   контроль Astra −2,6% — падение специфично для KES. Пороги и правила метрик настраиваются в интерфейсе.
2. **Расследование (многошаговый агент).** 7 шагов по эталонному кейсу: что изменилось → контроль → релизы в окне
   (ранжирование кандидатов) → воронка → пробелы в данных → внешние источники (цитаты аналитика, интервью, конкуренты,
   поиск Яндекса) → вывод. Главный кандидат — релиз R-09 (новый конфигуратор KES); участок «конфигуратор → корзина»
   не измеряется (задача T-08). Причина называется «главным кандидатом», пока гипотеза не проверена замером.
3. **Действия по кнопке ПМа.** Задача в бэклоге с тегом «сгенерирована ИИ-помощником»; повышение приоритета связанной
   задачи T-08; гипотеза с измеримым критерием успеха и правилом закрытия; письмо ПМу с доказательствами —
   отправляется на тестовый ящик по SMTP (Яндекс Почта); сообщение для Dion; экспорт задач в Redmine (JSON и CSV).
   Тег «изменена ИИ-помощником» ставится только на изменения агента, не на действия человека.
4. **Замер эффекта после релиза.** Сравнение с базой и контролем; вердикт «подтверждена» закрывает задачу,
   «не подтверждена» — возвращает её в работу.
5. **Справка для отдела продаж** (повторяющиеся объяснения ПМа — бизнес-проблема задачи): аргументы, сравнение с
   конкурентами (только сопоставимые SKU), ответы на типовые вопросы клиентов, возражения, «что нельзя обещать»,
   сообщение в канал продаж, сценарий видеообзора карточки товара. Каждый тезис со ссылкой на источник.
   Агент читает живую карточку store.softline.ru (цена, редакции, сроки) и проверяет её качество —
   нашёл на карточке KES текст-заглушку «Lorem ipsum» под ценой.
6. **Чат с агентом** (Ctrl+K): отвечает по фактам из данных, итогам расследований, справке и 15 типовым вопросам,
   проверенным аналитиком; по запросу ищет в интернете через Yandex Search API.
7. **База знаний:** поиск по интервью и конкурентному анализу, загрузка новых исследований (xlsx, csv, txt, md).
8. **Живой счётчик Яндекс.Метрики** команды (Reporting API) на стенде; учёт токенов по шагам агента для расчёта стоимости.
9. **Интерфейс:** радар, сквозная история «от сигнала до вердикта», расследования, письма, бэклог-борд,
   «Продажам», знания, настройки; мобильная версия.

## Не реализовано / ограничения
- **Redmine и Dion** — без живого подключения: задачи выгружаются в формате Redmine (JSON для REST API, CSV для импорта),
  сообщение для Dion формируется; по ответу организаторов этого достаточно для демо.
- **Метрика магазина** — нет доступа к счётчику store.softline.ru; подключён тестовый счётчик команды,
  метрики кейса берутся из датасета задачи.
- **Замер эффекта** — на синтетических «после-релизных» данных: реальных данных после хотфикса в задаче нет.
- **Тестовый ЛК магазина** не использовался: вход защищён капчей; агент работает с публичной карточкой товара.
- **Видеообзоры** — агент пишет сценарий видеообзора карточки, само видео не генерирует.
- Состояние (бэклог, гипотезы, расследования) хранится в JSON-файлах на сервере, без БД и без разграничения доступа.

## Подход и архитектура
Принцип: **цифры считает код, модель только интерпретирует.** Детектор и расчёты детерминированные, LLM получает
готовые факты и пишет отчёт в строгом JSON; без ключа LLM отчёт собирается по шаблону из тех же фактов.

Память (загрузка датасета, BM25-поиск по документам) → Радар (детектор) → Следователь (сбор доказательств + LLM +
поиск Яндекса + витрина) → Курьер (задача, приоритеты, гипотеза, письмо) → ПМ → Замер эффекта.

## Стек и модели
- Бэкенд: Python 3.12, FastAPI, pandas, openpyxl, httpx, rank-bm25.
- Фронтенд: React 18, TypeScript, Vite, ECharts, react-router.
- LLM: **Qwen3.6-35B-A3B** (open weights, Apache 2.0; ~20 ГБ в Q4 — укладывается в 128 ГБ VRAM) через Yandex AI Studio,
  OpenAI-совместимый API, `reasoning_effort=low`. Провайдер меняется переменными окружения — подходит vLLM/Ollama
  с той же моделью в контуре заказчика.
- Поиск: Yandex Search API. Аналитика: Яндекс.Метрика Reporting API. Почта: SMTP.

## Запуск и состав поставки
- Репозиторий: бэкенд (`backend/`), фронтенд (`frontend/`), данные задачи и проверенные аналитиком материалы (`data/`),
  документация API (`docs/api.md`, `.html`, `.docx`), развёртывание (`Dockerfile`, `deploy/`).
- Локально: `pip install -r requirements.txt`, `cp .env.example .env`, `uvicorn backend.app.main:app` — инструкция в README.
- Стенд: VPS в РФ (Ubuntu 24.04, 1 vCPU / 1 ГБ), systemd + Caddy (HTTPS). Также собирается одним Docker-образом.
- Ключи — только в переменных окружения, в репозитории их нет.

## Сторонние компоненты и ранее созданные наработки
Ранее созданных наработок команды нет. Используются открытые библиотеки (FastAPI, pandas, React, ECharts и др.),
открытая модель Qwen3.6-35B-A3B, сервисы Яндекса (AI Studio, Search API, Метрика, Почта). Разработка велась с помощью
ИИ-ассистента для программирования (Claude Code).

## Экономика
Расчёт стоимости одного запроса — в калькуляторе (ссылка в форме). Токены на один вызов, замер на стенде:
расследование ≈ 8 650 вход / 5 800 выход; вопрос в чат ≈ 2 750 / 3 700; справка для продаж ≈ 8 700 / 8 000–10 000.

Поиск в интернете (Yandex Search API)

GET /api/web/search?q=купить kaspersky endpoint security&k=5

Ответ:

{"ok": true, "query": "…", "source": "Yandex Search API",
 "results": [{"url": "…", "domain": "…", "title": "…", "snippet": "…"}]}

Без ключа: {"ok": false, "results": [], "error": "Yandex Search API не настроен …"}. В /api/health — web_search.configured. Результаты также попадают в отчёт расследования (evidence.web) и в чат (facts.web, если в вопросе «поищи в интернете», «конкуренты», «рынок» и т.п.). Сводка аналитика по внешним источникам — evidence.analyst_evidence. Её точные цитаты идут первыми в evidence.interviews / evidence.competitors (тот же формат фрагмента плюс curated: true, finding — вывод аналитика, supports_hypothesis) и в steps[n=6].quotes отчёта.

Тег задачи «изменена ИИ-помощником» ставится только при изменениях от агента (курьер поднял приоритет, замер закрыл задачу). PATCH /api/backlog/tasks/{id} от человека тег не ставит; в history[].by — pm или ai.

Почта (отправка на тестовый ящик)

При POST /api/investigations/{id}/apply письмо ПМу сохраняется в outbox/*.eml и, если настроен SMTP (SMTP_USER, SMTP_PASSWORD, MAIL_TO), отправляется. В ответе email.sent: {"ok": true, "to": "…", "at": "…"} или {"ok": false, "error": "…"}. email.to — адресат.

  • POST /api/investigations/{id}/send-email — отправить ещё раз;
  • POST /api/sales-briefs/{id}/send — разослать справку отделу продаж;
  • GET /api/mail/log — журнал отправленных писем; в /api/health — mail.configured, mail.to.

Экспорт бэклога в Redmine

  • GET /api/backlog/tasks/{id}/redmine — JSON для POST /issues.json (Redmine REST API);
  • GET /api/backlog/redmine.csv?ai_only=true — CSV (;, UTF-8) для импорта задач в Redmine; ai_only — только задачи агента.

GET /api/storefront/card?family=KES → {"ok": true, "url": "…", "title": "…", "prices_rub": [23220], "excerpt": "текст карточки", "issues": ["В HTML карточки скрытый текст-заглушка «Lorem ipsum» под ценой (покупателю не виден)"], "fetched_at": "…"}. Справка для отдела продаж

Бизнес-проблема задачи — ПМ тратит часы на одни и те же объяснения продавцам. Агент собирает шпаргалку по продукту из конкурентного анализа, интервью, сводки аналитика, сигналов, релизов и поиска Яндекса; каждый тезис со ссылкой на источник.

POST /api/sales-briefs {"product": "KES"} — синхронно, ~30–50 с с LLM (без ключа — шаблон из цитат аналитика). Ответ:

{"id": "SB-1A2B3C", "created_at": "…", "mode": "llm", "family": "KES", "tag": "сгенерирована ИИ-помощником",
 "product": "Kaspersky Endpoint Security для бизнеса",
 "pitch": "2–3 предложения для клиента",
 "who_buys": ["…"],
 "key_points": [{"text": "…", "source": "E-01 | <id фрагмента> | URL"}],
 "vs_competitors": [{"competitor": "allsoft.ru", "point": "…", "source": "…"}],
 "faq": [{"q": "…", "a": "…", "source": "…"}],
 "objections": [{"objection": "…", "answer": "…", "source": "…"}],
 "dont_say": ["чего нельзя обещать — нет данных"],
 "internal_note": "для ПМа: сигналы и релизы по продукту",

 "evidence": {"analyst_quotes": [], "competitors": [], "interviews": [], "signals": [], "releases": [], "web": []}}

product — KES, Astra или любое название (поиск по базе знаний). GET /api/sales-faq?family=KES — типовые вопросы с ответами от аналитика (data/curated/sales_faq.json, как есть); они же идут в справку (evidence.analyst_faq) и в чат (facts.analyst_faq). Сводка аналитика по Astra — data/curated/evidence_astra.json (тот же формат, что по Kaspersky) — подхватывается автоматически. GET /api/sales-briefs — список (без evidence), GET /api/sales-briefs/{id} — целиком. Чат подхватывает последнюю справку по упомянутому продукту (facts.sales_brief) — типовые вопросы отвечаются по ней. Токены — шаг sales_brief в /api/usage/tokens.

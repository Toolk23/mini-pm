## 1. Что сделано за 48 часов и что нет
Работает и показано в видео (на данных задачи):
1. Радар: детектор находит устойчивые отклонения — скользящее среднее за 4 недели, разовые всплески исключаются (медиана 4 недель × 1,35), неполная неделя помечается, обязательна контрольная группа. Кейс: самостоятельные заказы KES −32,7% (165,8 → 111,6), контроль Astra −2,6% → падение специфично для KES.
2. Расследование — 7 шагов: что изменилось → контроль → релизы в окне (ранжирование) → воронка → пробелы в данных → внешние источники (цитаты интервью и конкурентного анализа, проверенные аналитиком, поиск Яндекса) → вывод. Главный кандидат — релиз R-09; участок «конфигуратор → корзина» не измеряется (T-08).
3. Действия по кнопке ПМа: задача в бэклог с тегом «сгенерирована ИИ-помощником», повышение приоритета T-08, гипотеза с критерием успеха и правилом закрытия, письмо ПМу с доказательствами — реально отправляется на тестовый ящик (SMTP), сообщение для Dion, экспорт задач в Redmine (JSON и CSV).
4. Замер эффекта после релиза: индекс вернулся к базе — задача закрывается, нет — возвращается в работу.
5. Справка для отдела продаж: аргументы, сравнение с конкурентами (только сопоставимые SKU), ответы на 15 типовых вопросов, возражения, «что нельзя обещать», сценарий видеообзора карточки. Агент читает живую карточку store.softline.ru (цена, редакции) и нашёл на карточке KES текст-заглушку «Lorem ipsum» под ценой.
6. Чат с агентом: отвечает по данным, итогам расследований и справке со ссылками на источники; поиск Яндекса по запросу.
7. База знаний с загрузкой новых исследований, настройки порогов без программиста, живой счётчик Яндекс.Метрики команды, учёт токенов по шагам.

Частично / на заглушках:
- Redmine и Dion — без живого подключения (экспорт в формате Redmine, текст сообщения для Dion; по ответу организаторов достаточно).
- Метрика магазина недоступна — метрики кейса из датасета, подключён тестовый счётчик команды.
- Замер эффекта — на синтетических «после-релизных» данных (реальных в задаче нет).
- Тестовый ЛК магазина не использовался (капча на входе) — работаем с публичной карточкой товара.
- Видеообзор карточки — только сценарий, видео агент не генерирует.
- Состояние в JSON-файлах, без БД и ролей.

## 2. Подход и архитектура
Путь: данные задачи (метрики, продажи, релизы, бэклог) и документы (интервью, конкурентный анализ) → Радар (детерминированный детектор) → сигнал → ПМ запускает расследование → агент собирает доказательства инструментами: ряды метрик и контроль, ранжирование релизов, связанные задачи бэклога, реестр разрывов учёта, BM25-поиск по интервью и конкурентам, проверенные цитаты аналитика, Yandex Search API, живая карточка store.softline.ru → LLM пишет отчёт → ПМ нажимает «Применить» → Курьер: задача с тегом, приоритеты, гипотеза, письмо → после релиза — замер эффекта.

Где решает модель: интерпретация собранных фактов — формулировка главного кандидата, гипотез, рекомендации, текста письма, справки для продаж и ответов в чате. Где не решает: все цифры (изменение, контроль, всплески, ранжирование релизов, замер эффекта) считает код; модель получает их готовыми.

Как проверяется ответ: строгий JSON-формат отчёта (с починкой типовых огрехов и повтором запроса); каждый тезис справки и чата — со ссылкой на источник (цитата E-01…, вопрос Q-01…, фрагмент базы, URL); причина называется «главным кандидатом», пока гипотеза не проверена замером; сигнал продаж выдаётся только при стабильной контрольной группе; «нет данных» не подменяется нулём; без LLM отчёт собирается по шаблону из тех же фактов. Решения применяет только человек (кнопка «Применить»).

## 3. Стек и модели
- Модель: Qwen3.6-35B-A3B (open weights, Apache 2.0; ~20 ГБ в Q4 — укладывается в 128 ГБ VRAM) через Yandex AI Studio, OpenAI-совместимый API, reasoning_effort=low. Провайдер меняется переменными окружения — подходит vLLM/Ollama с той же моделью в контуре заказчика.
- Поиск: Yandex Search API; веб-аналитика: Яндекс.Метрика Reporting API; почта: SMTP (Яндекс Почта); поиск по документам: BM25 локально (rank-bm25), без внешних эмбеддингов.
- Бэкенд: Python 3.12, FastAPI, uvicorn, pandas, openpyxl, httpx.
- Фронтенд: React 18, TypeScript, Vite, ECharts, react-router.
- Хранение: JSON-файлы состояния (бэклог, гипотезы, расследования, лог токенов), без БД.
- Хостинг: VPS в РФ (Timeweb Cloud, Ubuntu 24.04, 1 vCPU / 1 ГБ), systemd + Caddy (HTTPS, Let's Encrypt).

## 5. Запуск и поставка
Состав: бэкенд (backend/), фронтенд (frontend/), данные задачи и проверенные аналитиком материалы (data/), документация API (docs/api.md, .html, .docx), развёртывание (Dockerfile, deploy/: systemd-сервис, Caddyfile, скрипт обновления), .env.example.
Запуск локально: pip install -r requirements.txt → cp .env.example .env (ключ Yandex AI Studio и ID каталога; Метрика и SMTP — по желанию) → uvicorn backend.app.main:app. Без ключа LLM работает в режиме шаблона. Также собирается одним Docker-образом.
Стенд открыт, логин не нужен. Swagger: https://77-233-220-24.sslip.io/docs

Пример запроса:
POST /api/investigations {"signal_id": "SIG-SALES-KES"} → через ~30 с GET /api/investigations/{id}:
{"status": "done", "report": {"mode": "llm", "summary": "<вывод: падение заказов KES на 32,7%, главный кандидат — релиз R-09, контроль Astra стабилен>", "steps": [7 шагов с источниками], "hypotheses": [...], "task": {...}, "success_criterion": "..."}}
Пример в чате: «Мы хуже allsoft по цене на Kaspersky?» → «По сопоставимой лицензии KL4863RAKFS Store дешевле: 33 182 ₽ против 36 870 ₽ [Q-10]».

# мини ПМ — ИИ-помощник продакт-менеджера интернет-магазина

Хакатон «ИИкузница 2026» · трек «Цифровой аватар» · заказчик «Софтлайн Решения» (store.softline.ru).

**Стенд:** https://77-233-220-24.sslip.io · Swagger: https://77-233-220-24.sslip.io/docs
(VPS в РФ, Timeweb Cloud; запасной стенд — https://mini-pm.onrender.com, бесплатный, засыпает без запросов)

## Что делает
Агент-следователь работает за продакт-менеджера по циклу «заметил → разобрался → предложил → проверил»:

1. **Радар** следит за метриками магазина и находит *устойчивые* отклонения, а не шум.
   Пример из данных: самостоятельные заказы Kaspersky (KES) упали на **−33%** (165,8 → 111,6),
   а контрольная группа Astra стабильна (**−3%**). Значит, причина в конкретном продукте, а не в сезоне или сайте.
2. **Следователь** собирает доказательства по всем источникам: метрики и воронка, релизы в окне падения,
   бэклог, интервью, конкурентный анализ, поиск Яндекса. Пишет отчёт из 7 шагов:
   главный кандидат — релиз R-09 (новые фильтры конфигуратора); участок «конфигуратор → корзина» не измеряется.
3. **Курьер** по одной кнопке ПМа:
   - создаёт задачу в бэклоге с тегом «сгенерирована ИИ-помощником» (экспорт в формате Redmine);
   - поднимает приоритет связанной задачи T-08 (учёт событий корзины);
   - заводит гипотезу с измеримым критерием успеха;
   - отправляет письмо ПМу с доказательствами на тестовый ящик (SMTP Яндекс Почты; копия — .eml)
     и готовит короткое сообщение для мессенджера (Dion);
   - выгружает задачи для Redmine (JSON для REST API и CSV для импорта).
4. **Замер эффекта** после релиза: индекс вернулся к базе — задача закрыта; не вернулся — гипотеза пересматривается.

5. **Справка для отдела продаж** — бизнес-проблема задачи: ПМ тратит 20–60 ч/мес на повторяющиеся объяснения.
   Агент собирает по продукту шпаргалку для продавцов: аргументы, сравнение с конкурентами (только сопоставимые цены),
   ответы на типовые вопросы клиентов из интервью, возражения и «что нельзя обещать» — каждый тезис со ссылкой на источник.
   Справка опирается на живую карточку товара store.softline.ru (цена, редакции, сроки) и проверяет её качество. К справке — сценарий видеообзора карточки
   на 60 секунд. Чат отвечает на повторяющиеся вопросы по справке и по 15 типовым вопросам, проверенным аналитиком.

6. **Проверка на живом магазине.** Путь покупки пройден в тестовом ЛК (28.11, обычный и верифицированный клиент):
   по умолчанию на карточке KES выбрано «Продление», а для продления на оформлении нужен скан предыдущей лицензии.
   Агент использует это как главную гипотезу; там же найдены риски учёта (add_to_cart в формате GA4, разные счётчики
   ЛК и магазина) — `data/curated/store_check_kes.json`.

Плюс чат с агентом (опирается на факты из данных и итоги расследований), база знаний с загрузкой новых
исследований и настройки порогов детектора без программиста.

## Принципы
- **Цифры считает код, а не модель.** Детектор детерминированный; LLM только интерпретирует факты
  и называет причину «главным кандидатом», пока гипотеза не проверена замером.
- **«Нет данных» ≠ ноль.** Пробелы учёта (неполная неделя, неизмеряемая корзина, всплески) помечаются явно.
- **Контрольная группа** обязательна: сигнал продаж выдаётся только при стабильном контроле.
- **Работает и без LLM**: если ключа нет, отчёт собирается по шаблону из тех же фактов.

## Модель и внешние сервисы
| Что | Чем | Почему |
|---|---|---|
| LLM | **Qwen3.6-35B-A3B** (Apache 2.0) через Yandex AI Studio, OpenAI-совместимый API | open weights, ~20 ГБ в Q4 — помещается в 128 ГБ VRAM, можно поднять в контуре заказчика |
| Поиск в интернете | Yandex Search API | единственный провайдер, доступный в контуре заказчика |
| Веб-аналитика | Яндекс.Метрика (тестовый счётчик команды) | Reporting API |
| Поиск по документам | BM25 локально | без внешних эмбеддингов, данные не покидают контур |
| Почта | SMTP (Яндекс Почта, пароль приложения) | письмо ПМу на тестовый ящик; в контуре — корпоративный SMTP |
| Витрина | публичная карточка store.softline.ru | живые цена и редакции; без входа в ЛК |

Провайдер LLM меняется только переменными окружения (`LLM_BASE_URL`, `LLM_MODEL`) —
подходит любой OpenAI-совместимый сервер (vLLM, Ollama и т.п.) с той же моделью внутри контура.
Токены логируются по шагам агента: `GET /api/usage/tokens` — исходные данные для калькулятора стоимости.

## Архитектура
```
Память (ingest, rag) → Радар (detector) → Следователь (investigator + LLM + websearch) → Курьер (courier) → ПМ
      ▲                                                                                   │
      └── загрузка новых исследований (/api/knowledge/upload)                  Замер эффекта (effect)
```
**Бэкенд** — Python 3.12, FastAPI, pandas (`backend/app`):
- `detector.py` — скользящее среднее, разовые всплески (медиана 4 недель × 1,35), неполная неделя,
  контрольная группа, окно релизов, реестр разрывов учёта;
- `investigator.py` — сбор доказательств, отчёт расследования, чат;
- `sales_brief.py` — справка для отдела продаж;
- `courier.py` — задача, приоритеты, гипотеза, письмо; `mailer.py` — отправка по SMTP; `effect.py` — замер эффекта;
- `storefront.py` — живая карточка товара store.softline.ru и проверка её качества;
- `llm.py` — OpenAI-совместимый клиент; `websearch.py` — Yandex Search API; `metrika.py` — Яндекс.Метрика;
- `rag.py` — поиск по интервью, конкурентному анализу и загруженным файлам;
- `settings_store.py` — пороги и правила метрик.

**Фронтенд** — Vite + React + TypeScript + ECharts (`frontend/`): радар, сквозная история «от сигнала до вердикта»,
расследования, письма, бэклог-борд, чат (Ctrl+K), база знаний, настройки. Есть режим моков для работы без бэкенда.

FastAPI отдаёт и API, и собранный фронтенд — у стенда один URL.

## Запуск локально
```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # вписать ключ LLM (и при желании токен Метрики)
.venv/bin/uvicorn backend.app.main:app --reload --port 8000
```
Фронтенд в режиме разработки: `cd frontend && npm install && npm run dev` → http://localhost:5173.
Или всё вместе: `docker build -t mini-pm . && docker run -p 8000:8000 --env-file .env mini-pm`.

Без ключа LLM всё работает, отчёты строятся по шаблону.

## Стенд (VPS)
Ubuntu 24.04, 1 vCPU / 1 ГБ: uvicorn как systemd-сервис (`deploy/minipm.service`), HTTPS через Caddy
(`deploy/Caddyfile`). Обновление — `deploy/deploy.sh`: фронт собирается локально, бэкенд подтягивается из GitHub.
Ключи лежат только в `/opt/mini-pm/.env` на сервере (в репозитории — `.env.example`).

## Данные
- `data/raw/` — исходные файлы заказчика, не изменяются;
- `data/curated/` — проверено аналитиком: сводки внешних источников по KES и Astra (цитаты с выводами),
  15 типовых вопросов продаж с ответами (`sales_faq.json`), снимок карточки товара;
- `data/synthetic_after/` — синтетические «после-релизные» данные для демонстрации замера эффекта;
- `data/state/` — состояние стенда: бэклог, гипотезы, настройки, лог токенов.

Документация API: [docs/api.md](docs/api.md) (то же в [HTML](docs/api.html) и [DOCX](docs/api.docx)).
Вопросы для демо чата: [docs/demo-questions.md](docs/demo-questions.md).
